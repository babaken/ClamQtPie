```text
 ├─ SchedulerError                # スケジュール関連
 │    ├─ JobValidationError

 ├─ DatabaseError                 # SQLite関連
 │    ├─ DatabaseConnectionError
 │    ├─ DatabaseMigrationError
 │    └─ DatabaseIntegrityError
 │
 ├─ ConfigError                   # 設定関連
 │    ├─ ConfigWriteError         # 書き込み権限エラー等
 │    ├─ ConfigValidationError
 │    └─ KeyringUnavailableError  # SMTPパスワード保存不可
 │
 ├─ NotificationError             # 通知関連
 │    ├─ MailSendError
 │    └─ DesktopNotifyError
 │
 └─ ProcessError                  # プロセス/権限関連
      ├─ PermissionDeniedError
      ├─ SingleInstanceError      # 多重起動検知（内部制御用、通常は例外化せず即終了だが将来のログ用に定義）

      └─ DefinitionUpdateError    # freshclamの実行失敗（E8004、Phase 11）
```

### 2.1 共通属性（AppError）

すべてのアプリ例外は以下の属性を持つ。

```python
class AppError(Exception):
    code: str        # 例: "E1001"
    message: str      # 人間可読メッセージ（GUI表示用、日本語）
    detail: str | None  # 内部詳細（ログ用、スタックトレースや元例外の文字列表現等）
```

- GUIへは`message`＋`code`のみを表示し、`detail`はログにのみ出力する（内部情報の過度な露出を避ける）

## 5. GUI表示ルール

### 5.1 エラーダイアログの共通フォーマット

```text
[アイコン] {message}

エラーコード: {code}
[詳細を見る ▼]（クリックでログ画面へ遷移、該当コードでフィルタ）

[OK]
```

- 「詳細を見る」リンクはログ画面（画面設計書7章）へ遷移し、キーワード検索欄に該当エラーコードを自動入力した状態で開く
- 上表で「GUI非表示」と定めたものはダイアログを出さずログ記録のみとする（頻発が想定される軽微なエラーでユーザー操作を妨げないため）

### 5.2 ログ出力フォーマットとの対応

ログ出力時は以下の形式でエラーコードを含める（ログ管理設計・ロギングフォーマット定義は別途検討課題、6章参照）。

```text
2026-07-13 10:00:00 [ERROR] [E1001] ClamAVサービスに接続できません: Connection refused (detail: ...)
```

## 6. 例外ハンドリング方針（共通ルール）

1. 各サービスクラス（ClamAVService等）内部では、下位ライブラリの例外（`socket.error`, `sqlite3.Error`等）を捕捉し、必ず対応するアプリ例外（`ClamdError`等、`code`付き）へ変換してから上位へ伝播させる。下位ライブラリの例外をそのままGUI層へ到達させない
2. GUI層（各画面のコントローラ）は`AppError`を捕捉して5.1節の共通ダイアログを表示する。`AppError`以外の例外が万一到達した場合はE9001として扱う
3. バックグラウンドスレッド（RealtimeManager、SchedulerService等）内で発生した例外はスレッド内で捕捉し、Qtシグナル経由でGUIスレッドへエラー情報を渡す（例外をスレッドをまたいで直接送出しない）

------------------------------------------------------------------------

## 6.1 ログのカテゴリ（Phase 11追加）

エラーコードの無い業務ログ（検知・スキャン開始/完了・隔離・復元・定義更新・監視の開始/停止等）は、`core/logger.py`の`log_event()`でカテゴリを明示して記録する（ログ行に` <スキャン>`等が入る）。ログ画面のカテゴリは「明示カテゴリ → エラーコード帯（3章） → どちらも無ければシステム」の順で決める。

------------------------------------------------------------------------

## 7. 未確定事項（次工程で決定が必要）

1. ログ出力の詳細フォーマット（項目・区切り文字・ローテーションファイル名規則）は「ロギングフォーマット定義書」として別途必要か
2. E9001（未分類エラー）が実装中に頻発する場合の是正フロー（都度この一覧書を更新するルールの明文化）
3. E8001（管理者権限不足）発生時、UAC再昇格を促す具体的な導線（再起動誘導ダイアログの要否）はインストーラ/パッケージング設計書で確定

## 8. 段階 12 改訂（v0.10.0: サービス化・WebUI）

v0.10.0 で、保護の処理はサービスが行い、トレイGUI・WebUI・`clamqtpie-ctl` は Web API でサービスに頼む形になった（インストーラ/パッケージング設計書 10 章）。それに合わせて E8100 番台を足し、表示する場所を改めた。1〜7 章と食い違うところは、この章が優先する。実装の記録は `clamav_frontend/README_DEV.md` の §55 以降。

### 8.1 エラーの伝わり方

- サービスの中で起きた `AppError` は、Web API の応答 `{"error": {"code", "message", "detail"}}` で返す。HTTP の状態コードは種類で決める（入力の誤り・断った要求 400、認証 401、権限 403、無い 404、競合 409、ロック 429、サービスの中の失敗 500）。500 のときは `detail` を返さず、ログにだけ残す
- トレイGUI は応答を同じコードの `AppError` に戻し、5.1 節のダイアログで出す。WebUI は画面の右下の知らせ（トースト）に「メッセージ [コード]」で出す。`clamqtpie-ctl` は端末に出して、0 以外の終了コードで終わる
- サービスが利用者向けの説明を付けて断ったとき（「監視するフォルダがありません…」など）は、その説明を `message` にする（トレイGUI のダイアログはメッセージとコードだけを出すため）
- 断った要求（E8100・E8102）はサービスのログに WARNING で残す。カテゴリは操作した機能のもの（スキャン・リアルタイム・更新・隔離。ほかはシステム）にする。ダイアログの「詳細を見る」（5.1 節）でコードから探せ、ログ画面のカテゴリでも絞り込める
- 6 章 3 の「Qt シグナル経由で GUI スレッドへ」は、サービスの中の扱い。サービスからトレイGUI・WebUI へは、API のイベント（SSE）と通知で知らせる

### 8.2 E8100 番台：Web API・サービス・昇格

| コード | 事象 | 例外クラス | メッセージ | 対応 |
|---|---|---|---|---|
| E8100 | API の処理の失敗。入力の誤りや、サービスが断った要求 | ApiError | 「API の処理でエラーが発生しました」。断った理由があればその文（例:「監視するフォルダがありません。先に監視するフォルダを追加してください」） | 入力を直してやり直す。断った要求はログに残す（8.1 節） |
| E8101 | 認証が必要（トークン・セッションが無い・切れた） | ApiAuthError | 「認証が必要です」 | WebUI はログインの画面に戻す。トレイGUI はサービスにつなぎ直す |
| E8102 | 管理者の権限が必要な操作を、一般の権限で頼んだ | ApiForbiddenError | 「この操作には管理者の権限が必要です」 | トレイGUI は昇格ヘルパー（UAC・polkit と確認画面）を通して 1 回だけやり直す。WebUI から変えられない項目（WebUI のログイン・二段階認証の設定など）は、トレイGUI か `clamqtpie-ctl` を案内する |
| E8103 | 接続元・接続先の名前（Host）・送り元（Origin）が許したものでない要求 | ApiRequestRejectedError | 「不正なリクエストのため拒否しました」 | 断る。WebUI は表示された URL（`clamqtpie-ctl web status`）で開き直す |
| E8104 | 別の処理を実行中（スキャン・定義更新・昇格の操作など） | ApiConflictError | 「別の処理を実行中のため受け付けられません」 | 終わってからやり直す |
| E8105 | サービスにつながらない（止まっている・起動の途中） | ServiceUnavailableError | 「ClamQtPie サービスに接続できません」 | トレイGUI はつながるまで待ち、`clamqtpie-ctl status` を案内する。ログに残すのは、つながらなくなったときの 1 回だけ |
| E8106 | WebUI のログインの失敗が続いた（接続元ごと、または LAN 全体）、確認コードの間違いが続いてログインを止めている | ApiLoginLockedError | 「ログインの失敗が続いたため、しばらく時間をおいてください」 | 時間をおく。確認コードの間違いで止めたときは、管理者が `clamqtpie-ctl web unlock`・トレイの「ログインの停止を解く」・パスワードの変更で解く |
| E8107 | サービスとトレイGUI の版数が違う | ServiceVersionMismatchError | 「サービスとトレイGUI の版数が一致しません。再インストールしてください」 | 導入し直す（更新の途中の古いトレイGUI など） |
| E8108 | WebUI の管理者の操作の前に、パスワードの再確認が要る | ApiReauthRequiredError | 「この操作の前に、確認コード（またはパスワード）を入力してください」 | WebUI は確認のダイアログでパスワードを求め、1 回だけやり直す（再確認から 5 分間は求めない） |
| E8109 | 指定した ID のものが無い（除外・監視するフォルダ・スケジュールなど。隔離は E3003） | ApiNotFoundError | 「対象が見つかりません」 | 一覧を読み直す |
| E8110 | この利用者はトレイGUI を使えない（ClamQtPie Users・`clamqtpie` グループに入っていない、入れた後にサインインし直していない） | ServicePermissionError | 「この PC の ClamQtPie を使う権限がありません」 | グループに入っていなければ `clamqtpie-ctl users add` を、入っているのに今のサインインに反映されていなければサインインし直し（だめなら再起動）を案内する |
| E8111 | 昇格（UAC・polkit の認証、ClamQtPie の確認画面）を取り消した | ElevationCancelledError | 「管理者の権限での操作を取り消しました」 | ダイアログは出さない。画面の変更は保存せずに残す |
| E8112 | 昇格ヘルパーを起動できない・途中で失敗した | ElevationError | 「管理者の権限で操作を実行できませんでした」 | ダイアログで出す（トレイGUI のリアルタイム保護・スケジュールの画面で、まとめた変更の途中で失敗したときは、何件目まで保存できたかを添え、一覧をサービスの今の内容に戻す） |

### 8.3 既存のコードの扱いの変更

| コード | 変更 |
|---|---|
| E2001 | メッセージを「監視するフォルダが見つかりません」にした（呼び方をそろえた。README_DEV §85） |
| E6001 | メッセージを「設定を保存できませんでした。設定ファイルの置き場所の空き容量と書き込み権限を確認してください」にした。設定はサービスが保存する（`%ProgramData%\ClamQtPie\config.json`・`/etc/clamqtpie/config.json`）。トレイGUI・WebUI から保存できない項目（保護された項目）は、E6001 ではなく画面で読み取り専用にし、`clamqtpie-ctl config set` を案内する |
| E6002 | Web API で変えられない項目・範囲の外の値も E6002 で断る |
| E6003 | SMTP パスワードは OS の keyring ではなく、サービスの秘密の保存先に置く。保存先が無いときに E6003 |
| E8001 | 使わない（4.8 節の「UAC 再昇格の導線」は昇格ヘルパーとして作った。権限が足りないときは E8102・E8111・E8112） |
| E8002 | 自動起動はトレイGUI が利用者ごとに登録する（Windows は `HKCU\...\Run`、Linux は自動起動の `.desktop`）。多重起動の防止（`SingleInstanceError`）はトレイGUI だけに残る |
| E8003 | clamd の開始・停止は管理者の操作（昇格を経る）。サービスは root・LocalSystem で動くため、Linux でも pkexec を使わない |
| E8004 | Linux でも freshclam をサービスが直接実行する（pkexec を使わない）。OS の定義更新サービス（clamav-freshclam）が動いている間は、自動・スケジュールの更新を見送る（履歴に記録しない。ログは見送りが始まったときだけ）。clamav-freshclam の開始・停止の失敗も E8004 |

### 8.4 7 章の未確定事項

- 3（E8001 の UAC 再昇格の導線）: 8.2 節の昇格ヘルパーで解決した
