# 画面設計書（ClamAVフロントエンド）

対象: PySide6製 GUIアプリケーション
前提: 基本設計書「1. 画面一覧」「2. 画面遷移」に準拠

------------------------------------------------------------------------

## 共通仕様

- ウィンドウ構成: メインウィンドウ（左ナビ＋右コンテンツ）＋タスクトレイ常駐
- 左ナビゲーション: ホーム／スキャン／リアルタイム／スケジュール／隔離／定義更新／ログ／設定 の8項目を固定表示
- ステータスバー（画面下部）: clamd稼働状態／定義DB更新日時／リアルタイム監視ON-OFFを常時表示
- 確認ダイアログ: 削除・復元・停止など破壊的操作は必ず確認ダイアログ（はい／いいえ）を挟む
- エラーダイアログ: 権限不足・clamd未起動・DB障害はモーダルダイアログで表示し、詳細は「ログ」画面へのリンクを添える

------------------------------------------------------------------------

## 1. ホーム画面

### 概要
ClamAV稼働状態、定義DB更新日時、リアルタイム監視状態を一覧表示するダッシュボード。

### レイアウト（上から）
1. ステータスカード（3分割）
   - clamdステータス（稼働中／停止／エラー、アイコン＋文字色で表現）
   - 定義DBバージョン・最終更新日時
   - リアルタイム監視 ON/OFF（トグルスイッチ）
2. クイックアクションボタン列
   - 「今すぐスキャン」「定義更新」「リアルタイム監視 開始/停止」
3. 直近アクティビティ一覧（テーブル、最大10件）
   - 日時／種別（スキャン・検知・更新・隔離）／概要

### 項目定義

| 項目名 | 種別 | データ元 | 備考 |
|---|---|---|---|
| clamdステータス | ラベル+アイコン | ClamAVService.ping() | 未起動時は「起動」ボタンを表示 |
| 定義DBバージョン | ラベル | ClamAVService.get_database_version() | |
| 最終更新日時 | ラベル | config/DB | freshclam実行結果を保存 |
| リアルタイム監視トグル | スイッチ | RealtimeManager.set_enabled() | OFF→ON時は確認不要、ON→OFF時は確認ダイアログ |
| 直近アクティビティ | テーブル | ログ／DB横断参照 | クリックで対応画面へ遷移 |

### 遷移
各カード／ボタンから対応画面（スキャン、リアルタイム、定義更新、ログ）へ遷移。

------------------------------------------------------------------------

## 2. スキャン画面

### 概要
ファイル／フォルダを指定したオンデマンドスキャンと進捗表示。

### レイアウト
1. スキャン対象選択エリア
   - ラジオボタン: 「クイックスキャン（ホーム/デスクトップ等）」「フルスキャン」「カスタム（ファイル/フォルダ選択）」
   - カスタム選択時: パス入力欄＋「参照」ボタン（複数パス追加可、リスト表示）
2. オプションエリア
   - 「サブフォルダを含む」チェックボックス（既定ON）
   - 「除外リストを適用」チェックボックス（既定ON）
3. 実行制御エリア
   - 「スキャン開始」／「停止」ボタン（排他制御）
   - 進捗バー（％表示）＋現在スキャン中のファイルパス（1行）
   - 検知件数・スキャン件数のリアルタイムカウンタ
4. 結果一覧テーブル（スキャン完了後 or 検知都度追記）
   - 列: ファイルパス／判定（正常・検知・エラー）／ウイルス名／検知日時
   - 検知行を選択し「隔離する」「無視する」ボタンで即時アクション

### 項目定義

| 項目名 | 種別 | 必須 | バリデーション |
|---|---|---|---|
| 対象パス | パス（複数可） | カスタム時必須 | 存在確認、アクセス権確認 |
| サブフォルダを含む | チェックボックス | - | 既定true |
| 除外リストを適用 | チェックボックス | - | 既定true |
| スキャン結果 | テーブル（読取専用） | - | ClamAVService.scan_file/scan_directoryの戻り値をバインド |

### 状態遷移
`待機中` → `スキャン中`（開始ボタン押下） → `完了`／`中断`（停止ボタン押下） → `待機中`

## 3. リアルタイム画面

### 概要
リアルタイム監視のON/OFFと、監視対象・除外設定を行う。Linux=clamonacc、Windows=watchdogだが、UI上は差異を意識させない。

### レイアウト
1. 監視状態トグル（ON/OFF）＋現在の監視方式ラベル（内部値、参考表示: 「clamonacc」／「watchdog監視」）
2. 監視対象パス一覧（テーブル＋追加/削除/有効-無効切替ボタン）
   - 空の場合は監視対象が未設定である旨を注記表示し、監視の開始ボタンを無効化する（既定の監視対象は持たない。Windowsリアルタイム監視詳細設計書3.1節に統一。Phase 11で矛盾を解消）
3. 除外設定タブ（サブタブ切替）
   - ファイル／フォルダ／拡張子／プロセス の4区分（要件定義4章対応）
   - 各区分ごとに一覧テーブル＋追加（入力 or 参照）／削除／有効-無効トグル
4. 検知時アクション設定
   - ラジオボタン: 「自動隔離」「通知のみ（手動対応）」

### 項目定義（excludeテーブル対応）

| 項目名 | 種別 | DB列対応 |
|---|---|---|
| 種別（ファイル/フォルダ/拡張子/プロセス） | セレクト | exclude.type |
| 値 | テキスト or パス選択 | exclude.value |
| 有効/無効 | チェックボックス | exclude.enabled |

### 注意事項
- ON→OFF切替時は確認ダイアログ「リアルタイム監視を停止しますか？」
- 除外リスト編集はリアルタイム監視のON/OFFに関わらず可能（保存時に反映）

## 4. スケジュール画面

### 概要
定期スキャン・定義更新ジョブの管理（APScheduler連携、scheduleテーブル対応）。

### レイアウト
1. ジョブ一覧テーブル
   - 列: 名前／種別（スキャン・定義更新）／スケジュール（人間可読表現、例: 毎日 3:00）／有効-無効／次回実行日時／最終実行結果
   - 行操作: 編集／削除／今すぐ実行
2. 「新規ジョブ追加」ボタン → ジョブ編集ダイアログを開く

### ジョブ編集ダイアログ 項目定義

| 項目名 | 種別 | 必須 | DB列対応 | 備考 |
|---|---|---|---|---|
| ジョブ名 | テキスト | 必須 | schedule.name | 重複不可 |
| 種別 | セレクト（スキャン／定義更新） | 必須 | schedule.scan_type | |
| 対象パス | パス（スキャン時のみ表示） | スキャン時必須 | schedule.target | |
| 実行周期 | プリセット（毎日/毎週/毎月/カスタムCron） | 必須 | schedule.cron | プリセット選択時はcron式を裏で自動生成、カスタム時は直接入力可 |
| 有効/無効 | トグル | - | schedule.enabled | |

### 実行結果表示
一覧の「最終実行結果」列は成功／失敗／検知ありをアイコンで区別し、クリックでログ画面へフィルタ遷移。

## 5. 隔離画面

### 概要
隔離済みファイルの一覧・復元・削除（quarantineテーブル対応）。

### レイアウト
1. フィルタ／検索バー（期間、ウイルス名、元パスの部分一致）
2. 隔離一覧テーブル
   - 列: 元ファイルパス／ウイルス名／検知日時／サイズ／SHA256（省略表示、ホバーで全体表示）／状態（隔離中／復元済／削除済）
   - 行操作ボタン: 「復元」「完全削除」「詳細表示」
3. 一括操作: チェックボックスで複数選択→一括削除

### 項目定義

| 項目名 | 種別 | DB列対応 |
|---|---|---|
| 元ファイルパス | ラベル | quarantine.original_path |
| ウイルス名 | ラベル | quarantine.virus_name |
| 検知日時 | ラベル | quarantine.detected_at |
| サイズ | ラベル | quarantine.size |
| SHA256 | ラベル（省略表示） | quarantine.sha256 |
| 状態 | バッジ | quarantine.restored / quarantine.deleted から算出 |

### 操作時の確認事項
- 「復元」: 復元先パス（既定=元パス、存在する場合は上書き確認 or 別名指定）を確認ダイアログで表示
- 「完全削除」: 「元に戻せません」の警告文を含む確認ダイアログ必須

## 7. ログ画面

### 概要
アプリケーションログの検索・フィルタ・CSV出力。

### レイアウト
1. フィルタバー
   - 期間（開始日～終了日）
   - ログレベル（DEBUG/INFO/WARNING/ERROR/CRITICAL、複数選択可）

### 項目定義

| 項目名 | 種別 | 備考 |
|---|---|---|
| 期間 | 日付範囲ピッカー | 既定は直近7日間 |
| ログレベル | チェックボックス群 | 既定は全選択 |
| カテゴリ | チェックボックス群 | 既定は全選択 |
| キーワード | テキスト | 空欄時はフィルタなし |

## 8. 設定画面

### 概要
config.jsonに対応する全体設定。サブタブで区分。

### サブタブ構成

**8-1. 一般**
- OS起動時自動起動（チェックボックス、保存時にOS側へ即時反映。失敗時はE8002を表示しチェックを元に戻す）
- ×ボタンでトレイに格納したときに案内を表示（チェックボックス、タスクトレイ常駐アプリプロセス設計書4.1節）
- ※「タスクトレイに常駐」の設定項目は設けない。×ボタンは常にトレイ格納とする（タスクトレイ常駐アプリプロセス設計書1章・config.jsonスキーマ定義書4.2節に統一。Phase 11で矛盾を解消）
- 言語（保留機能のため本画面では非表示）

**8-2. SMTP（通知）**
- ホスト／ポート／ユーザー名／パスワード（マスク表示）／送信元アドレス／宛先アドレス
- 暗号化方式（なし／SSL／STARTTLS）
- 「テスト送信」ボタン

**8-3. 通知**
- 検知時にメール通知（チェック）
- 検知時にデスクトップ通知（チェック）
- 定義更新失敗時に通知（チェック）
- スケジュールジョブ失敗時に通知（チェック）

**8-4. リアルタイム監視（既定値）**
- リアルタイム画面の初期状態（起動時ON/OFF）
- 検知時アクションの既定値（自動隔離／通知のみ）

**8-5. 定義更新**
- 自動更新の有効/無効
- 自動更新の実行間隔（時間単位、既定4時間）
- freshclamの場所（入力欄＋「参照...」。既定「freshclam」はPATHから探す。空欄で保存すると「freshclam」に戻す。コードレビューで追加）

**8-6. ログ**
- 保持期間（30/60/90/180/365日、既定90日）
- ログレベル（出力する最小レベル）

**8-7. ClamAV エンジン**（コードレビュー後に追加。タブは「一般」の次に置く）
- 接続方式（自動（Windows: TCP / Linux: UNIX ソケット）／TCP／UNIX ソケット。UNIX ソケットはLinuxのみ）。選んだ方式で使う欄だけを有効にする
- ホスト／ポート（1〜65535）／UNIX ソケット（Linuxのみ表示）。ホスト・UNIX ソケットを空欄で保存すると既定値に戻す
- 「接続テスト」: 入力中（保存前）の接続先へPINGし、結果（エンジンと定義DBの版、または接続できない理由）をボタンの右に表示する。バックグラウンドで実行する
- 接続の設定はclamd.confのTCPSocket / TCPAddr / LocalSocketと同じ値にすること、保存した接続の設定はアプリの再起動後に反映されることを画面に表示する
- OSのサービス名（空欄ならOSの既定）、停止を検知したら自動で起動（チェック）。保存直後から使う
- clamonaccの場所（Linuxのみ表示）。次にリアルタイム監視を開始したときから使う（起動時にclamonaccが見つからずwatchdog方式になっている場合はアプリの再起動が必要）

### 項目定義（config.json対応、抜粋）

| セクション | キー例 | 型 | 既定値 |
|---|---|---|---|
| general | autostart | bool | true |
| general | show_tray_hint_shown | bool | false（「案内を表示」チェックの反転） |
| smtp | host, port, user, password, from, to, encryption | string/int | 空 |
| notification | on_detect_mail, on_detect_desktop, on_update_fail, on_job_fail | bool | true/true/true/true |
| realtime | default_enabled, default_action | bool/string | false / "quarantine"（初回は監視対象0件で開始できないためfalse。Phase 11でスキーマ定義書・実装に統一） |
| clamd | connection_type, tcp_host, tcp_port, unix_socket_path, service_name, auto_start | string/int/bool | "auto" / "127.0.0.1" / 3310 / "/var/run/clamav/clamd.ctl" / "" / true（8-7） |
| realtime | clamonacc_path | string | "clamonacc"（8-7、Linuxのみ） |
| update | auto_update, interval_hours, freshclam_path | bool/int/string | true / 4 / "freshclam" |
| logging | retention_days, level | int/string | 90 / "INFO" |

保存/キャンセルボタンは画面下部に固定表示。「保存」時はconfig.jsonへ書き込み、即時反映が必要な項目（自動起動、ログ保持期間等）は保存直後に該当サービスへ再読込を通知する。

## 11. Phase 11 改訂（設計書と実装の突き合わせ結果の反映）

設計書と実装を突き合わせ、未実装だった機能の実装と、実装で確定した仕様を以下に反映する。

### 11.1 共通
- 一覧テーブルは読み取り専用・行単位選択とし、最終列（2列の表はパス／値の列）を幅いっぱいに広げる。表・ログ表示は画面の残りの高さいっぱいに広げる
- すべてのエラーダイアログに「詳細を見る」（ログ画面へ遷移し、エラーコードで絞り込む）を付ける
- ステータスバー・ホーム画面のカード・トレイアイコンは同じ稼働状態から更新する。clamdの状態は60秒ごと（定義更新完了時・検知時も）、リアルタイム監視のON/OFFは2秒ごとに更新する

### 11.2 ホーム画面（1章）
- clamdステータスは文字色で区別する（稼働中=緑、停止=赤）。停止中は「起動」ボタンを表示し、OSのサービスとして起動する（Windows: サービス「clamd」、Linux: clamav-daemon。clamdソケット通信プロトコル設計書9章）
  - 画面レイアウトの刷新（README_DEV.md §33）で、「起動」ボタンは「ClamAV エンジン サービス」画面の「サービスを開始」に移した（ホーム画面には置かない）
- 「最終更新日時」は定義DBのビルド日時（clamd VERSION応答）を表示する
- リアルタイム監視の開始/停止はトグルスイッチではなくボタンとし、停止時は確認ダイアログを表示する（トレイメニューからの停止も同様）
- 直近アクティビティはログのうちカテゴリ「スキャン／リアルタイム／更新／隔離」のINFO以上を新しい順に最大10件表示する。行・カードのクリックで対応画面へ遷移する（clamd→ログ、定義DB→定義更新、リアルタイム→リアルタイム監視）
- 「今すぐスキャン」はスキャン画面へ遷移してクイックスキャンを開始する

### 11.3 スキャン画面（2章）
- クイックスキャン: デスクトップ・ダウンロード・ドキュメント・一時フォルダ（Windowsはスタートアップフォルダも）。OS標準のフォルダ位置（Qt QStandardPaths）を使うため、フォルダの移動（OneDrive等）にも追従する
- フルスキャン: システムドライブのみ（Windows: %SystemDrive%\、Linux: / から /proc・/sys・/dev・/run を除く）
- カスタム: 「フォルダ追加」「ファイル追加」「削除」。開始時に対象の存在を確認し、無い場合は開始しない
- 結果一覧は「検知」「エラー」の行のみ追記する（正常ファイルは件数のみ。フルスキャンで数十万行になるのを避けるため）
- 「無視する」は検知行を一覧から外し、対応しなかったことをログ（WARNING）に記録する
- 状態表示（待機中／スキャン中／完了／中断）を追加。clamdに接続できない場合はエラーを1回だけ表示してスキャンを中断する
- 進捗・件数の表示は200ms間隔でまとめて更新する（非機能要件詳細2.3節）

### 11.4 リアルタイム画面（3章）
- 方式ラベルには実際に使っている方式（「watchdog監視」／「clamonacc」）を表示する
- 監視対象が1件も無い場合は、画面の初回表示時に「今すぐ追加／後で設定する」の案内を表示し（起動ごとに1回）、監視の開始ボタンを無効化してツールチップで理由を示す
- 除外設定は区分ごとに「除外を追加」（ファイル/フォルダは参照ダイアログ、拡張子/プロセスは文字入力。拡張子は先頭の「.」を補完）・「除外を削除」（確認あり）・「除外の有効/無効を切替」を行う。同じ値の重複登録はしない
- 監視中に監視対象フォルダが消えた場合はE2001をダイアログ表示する
- clamdに接続できない間は、検査できなかったファイルごとにはエラーを表示しない。接続できなくなった最初の1回だけエラーダイアログを出し（ログにも記録）、次に検査できた時点で解除する。エラーダイアログの表示中に届いたエラーは重ねて表示しない（コードレビューで修正。以前はファイルのイベントごとにダイアログが積み重なった）
- ホーム画面・トレイから監視を開始/停止した場合も本画面のボタン表示を合わせる

### 11.5 スケジュール画面（4章）
- 種別は「スキャン／定義更新」、スケジュールは「毎日 3:00」「毎週日曜 3:00」「毎月1日 3:00」等の人間可読表現で表示する（該当しない形はcron式のまま。ツールチップでcron式を表示）
- 次回実行日時はAPSchedulerの値を表示する。最終実行結果は「日時＋成功／失敗／検知あり n件」の文字で表示し（アイコンは使わない）、ダブルクリックでジョブ名で絞り込んだログ画面へ遷移する
- 有効/無効は一覧の「有効/無効を切替」ボタンで切り替える（ジョブ編集ダイアログには置かない）
- 「今すぐ実行」はバックグラウンドで実行し、最終実行結果欄に「実行中...」を表示する。同じジョブの実行中はE4004
- ジョブ編集ダイアログは、ジョブ名必須・スキャン時の対象パスの存在・cron式の妥当性をOK押下時に確認し、エラーはダイアログ内に赤字で表示する（閉じない）
- cron式の曜日は標準のcronの数え方（0と7が日曜、1が月曜…6が土曜。sun〜satの名前も可）で解釈する。APSchedulerのfrom_crontabは0を月曜として扱うため、曜日欄を名前に変換して渡す（コードレビューで修正。以前は「毎週日曜 3:00」が月曜に実行されていた）

### 11.6 隔離画面（5章）
- フィルタは「元パス・ウイルス名のキーワード」と「期間（チェックで有効化）」
- SHA256は先頭12文字＋「…」で表示し、ツールチップで全体を表示する。サイズはKB/MB等で表示する
- 一括操作はチェックボックスではなく、行の複数選択（Ctrl/Shift）で行う。完全削除は「隔離中」の行のみが対象
- 復元先に同名ファイルがある場合は「上書き／別名で保存／キャンセル」を選ぶ
- 「詳細表示」は全項目（UUID・SHA256全体を含む）を表示する
- 隔離画面を開くと一覧を再読込し、トレイの「検知あり」表示を解除する

### 11.7 定義更新画面（6章）
- 自動更新の状態（「有効（4時間ごと）」等）と「設定を変更」ボタン（設定画面へ遷移）を表示する

### 11.8 ログ画面（7章）
- カテゴリは「スキャン／リアルタイム／更新／隔離／スケジュール／通知／システム」とする（エラーコード帯から推定されるスケジュール（E4000番台）・通知（E7000番台）を追加）。業務ログはログ行に明示したカテゴリ（例: `<スキャン>`）、それ以外はエラーコード帯、どちらも無い行は「システム」
- 他画面から遷移した場合は最新のログを読み直してからキーワードで絞り込む
- 画面を開くたびに最新のログを読み直す。期間の終了日が前回の「今日」のままなら、同じ日数の期間のまま今日まで進める（常駐したまま日をまたいでも最近のログが出るように）
- 日付付きの過去のファイル（`app.log.YYYY-MM-DD`）も読む（ホームの直近アクティビティは直近7日分）。以前は現在の`app.log`だけを読み、日次のローテーション後は前日以前のログが表示されなかった（コードレビューで修正）
- 「ログをクリア」ボタン（「CSV出力」の右）: 確認ダイアログ（「元に戻せません。必要なら先にCSV出力」）の後、アプリのログをすべて消去する。`app.log`は書き込み中のため中身を空にし（Windowsでは開いているファイルを削除できない）、日付付きの過去のファイル（`app.log.YYYY-MM-DD`）は削除する。消去後に「ログをクリアしました（過去のログファイル n件を削除）」（カテゴリ「システム」）を1行記録する。clamonaccのログ（`clamonacc/clamonacc.log`）は対象外。ホーム画面の直近アクティビティもログから作るため空になる

### 11.9 設定画面（8章）
- 保存直後にログ設定（レベル・保持期間）と自動更新ジョブ（有効/無効・間隔）を反映する。リアルタイム監視の検知時アクションの既定値はリアルタイム画面にも反映する
- freshclamの場所は保存直後から定義更新に使う（実行中の更新はそのまま）
- 「ClamAV エンジン」タブ: 接続の設定はアプリの再起動後に反映する（ClamAVServiceは起動時の設定の写しを使い、通信中に接続先が変わらないようにする）。サービス名はエンジン サービス画面の表示・停止・起動に保存直後から反映する
- 検知時アクションの既定値は「自動隔離／通知のみ（手動対応）」と表示する
- 画面を開くたびに現在の設定を読み直す（リアルタイム画面で変えた検知時アクション、×ボタンでの案内の表示済み等を、保存時に古い入力値で上書きしないため。コードレビューで修正）
- 自動更新の初回は、前回の定義更新（手動・自動・スケジュール、失敗を含む）から実行間隔が過ぎた時点とする。既に過ぎていれば（履歴が無い場合も）起動の約2分後に実行する。間隔が変わらない再登録（自動更新と関係のない設定の保存）では次回の実行時刻を変えない（コードレビューで修正。以前は起動・保存から間隔の後が初回で、起動から4時間以内にPCを終了すると自動更新が一度も実行されないことがあった）

### 11.10 タスクトレイ（9章）
- 「今すぐスキャン」は画面を開かずにクイックスキャンを実行し、開始時と完了時に吹き出し通知する
- 「検知あり」はリアルタイム監視・スケジュールスキャンの検知で表示し、隔離画面を開いた時点で解除する
- アイコン素材はオリジナル図案（scripts/generate_icons.py で生成）。素材が無い場合はQt標準アイコンで代替する
