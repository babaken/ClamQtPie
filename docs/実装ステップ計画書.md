# 実装ステップ計画書

対象: ClamAVフロントエンド（PySide6）
前提: 要件定義書、基本設計書、詳細設計書、および画面設計書〜非機能要件詳細の11設計書すべて

------------------------------------------------------------------------

## 1. 全体方針

- 依存関係の少ない「土台」（設定・DB・例外・clamd通信）から着手し、その上に機能（スキャン・隔離・監視・通知）を積み上げ、最後にプロセス制御・パッケージングで仕上げる順序とする
- 各フェーズの終わりに、テスト仕様書のケースID・手動確認チェックリストを使って完了判定を行う（フェーズを跨いで手戻りしないよう、下位フェーズの単体テストを通してから上位フェーズへ進む）
- GUI（画面設計書）は機能実装と並行して「見た目だけ先に作る」ことも可能なため、フェーズ3以降は機能側とGUI側をある程度並行して進められる想定

------------------------------------------------------------------------

## 2. フェーズ構成と依存関係（概観）

```text
Phase 0: 環境構築
   ↓
Phase 1: 土台（config / DB / 例外 / ロギング）
   ↓
Phase 2: clamd通信コア（ClamdClient / ClamAVService）
   ↓
   ├─ Phase 3: GUIスケルトン（8画面の枠＋ナビゲーション）
   │
   ├─ Phase 4: スキャン機能（オンデマンドスキャン画面〜隔離）
   │      ↓
   │   Phase 5: リアルタイム監視（Windows優先）
   │      ↓
   │   Phase 6: スケジュール機能
   │
   └─ Phase 7: 通知機能（Phase4〜6の検知イベントに接続）
          ↓
Phase 8: タスクトレイ・プロセス統合（多重起動防止・自動起動・常駐化）
   ↓
Phase 9: パッケージング（PyInstaller/Zip配布）
   ↓
Phase 10: 結合テスト・手動確認・性能検証（非機能要件）
   ↓
Phase 11: リリース準備
```

各フェーズの詳細を以降に記載する。

## 3. 各設計書の「未確定事項」のうち、実装着手前に解消しておくべきもの

以下は実装を始めると手戻りが大きくなるため、該当フェーズ開始前に優先的に決定しておくことを推奨する。

| 未確定事項 | 関連フェーズ | 対応時期の目安 |
|---|---|---|
| SQLite DBファイル名（→app.dbで決定済み） | Phase 1 | 解消済み |
| Windows自動起動とUAC常時プロンプトの整合（タスクスケジューラ方式への変更要否） | Phase 8 | Phase 8着手前に方針確定（変更する場合、レジストリ実装が無駄になるため） |
| Linuxリアルタイム監視（clamonacc連携）の詳細設計 | Phase 5 | Phase 5でWindows優先実装後、Linux版着手前に別途詳細設計書を追加するか判断 |
| コード署名の要否 | Phase 9 | Phase 9着手前（署名する場合、ビルドパイプラインに追加工程が必要） |
| デバウンスタイマー実装のメモリ超過時の代替方式 | Phase 5, 10 | Phase 10の性能実測後、超過していれば対応 |
