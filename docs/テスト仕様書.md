## 2. テスト方針

### 2.1 テストレベルの区分

| レベル | 対象 | 実施方法 |
|---|---|---|
| ユニットテスト | 各サービスクラスの単体ロジック（clamd応答パース、デバウンス処理、除外リスト照合、バリデーション等） | pytest、外部依存（clamdソケット、ファイルシステム、レジストリ、keyring）はモック化 |
| 結合テスト | サービス間連携（検知→隔離→通知の一連の流れ、DB↔サービス連携） | pytest、実際のSQLite（一時ファイル）を使用、clamdはモックまたはEICARテストファイルによる実clamd連携（3.4節） |
| 手動確認 | GUI操作、実OS環境依存の挙動（UAC、トレイアイコン、Toast通知の見た目等） | 6章のチェックリストに基づき手動実施 |

### 2.2 ディレクトリ構成

```text
tests/
  unit/
    test_clamd_client.py
    test_realtime_debounce.py
    test_quarantine_service.py
    test_scheduler_service.py
    test_config_service.py
    test_notification_aggregator.py
    test_database_migration.py
    test_exceptions.py
  integration/
    test_scan_to_quarantine_flow.py
    test_realtime_to_notification_flow.py
    test_db_service_integration.py
    test_config_roundtrip.py
  fixtures/
    eicar.txt              # EICARテストファイル（3.4節）
    sample_config.json
    conftest.py             # 共通fixture（一時DB、モックclamdサーバ等）
```

### 2.3 実行方法

```bash
# 全テスト実行
pytest

# カバレッジ計測（目安80%）
pytest --cov=core --cov=db --cov=gui --cov-report=term-missing

# ユニットのみ / 結合のみ
pytest tests/unit
pytest tests/integration
```

## 4. モック・テスト用具の方針

| 対象 | モック方法 |
|---|---|
| clamdソケット通信 | `unittest.mock`でソケットオブジェクトをモック化し、任意の応答文字列を返すテスト用フェイクサーバ（`conftest.py`にfixture化）を用意する。結合テスト（3.4節相当）のみ実clamdを使用 |
| watchdog（ファイルシステムイベント） | ユニットテストでは`FileSystemEventHandler`のイベントオブジェクトを直接生成してハンドラへ渡す（実ファイルシステム監視は結合テストのみ） |
| レジストリ（自動起動） | `winreg`呼び出し箇所を`unittest.mock.patch`で差し替え、Windows以外の開発環境でもテスト実行できるようにする |
| keyring | `keyring`ライブラリの`keyring.backends.SecretService`等をテスト用インメモリバックエンド（`keyring`が提供する`keyrings.alt`のテスト用バックエンド、または簡易モック）に差し替える |
| SMTP送信 | `smtplib.SMTP`をモック化し、実際のメール送信は行わない |
| PowerShell / notify-send呼び出し | `subprocess.run`をモック化し、呼び出しコマンド・引数のみ検証する（実際の通知表示確認は手動、6章） |
| 日時・タイマー | `freezegun`等の時間操作ライブラリの利用を検討し、デバウンス・集約ウィンドウのテスト（RT-U01, NT-U01等）を実時間待機なしで実行可能にする |

## 5. EICARテストファイルの利用（実clamd結合テスト）

- 実際のウイルスを使わず、業界標準のテスト用検体「EICARテストファイル」を`tests/fixtures/eicar.txt`として同梱し、clamdが正しく`FOUND`判定することを確認する結合テストに使用する
- EICARファイルはウイルス対策ソフト自体に検知される可能性があるため、リポジトリのバージョン管理除外設定や開発環境のウイルス対策ソフト側の除外設定が必要になる場合がある旨をREADME（開発者向け）に注記する
- 実clamdが利用できないCI環境や開発者のPC環境では、CLM-I01等の実clamd結合テストは`pytest.mark.skipif`でスキップ可能にする（clamdの起動有無を`ping()`で事前判定）

- `python -m pytest -q`（GUIはoffscreenで実行）。想定外のモーダルダイアログが表示されたテストは即時失敗とする（無限停止の防止）
