# インストーラ/パッケージング設計書

対象: PyInstallerによるビルド・配布物構成、Windows起動時権限制御
前提: 要件定義書「初版実装機能」、config.jsonスキーマ定義書2章（ポータブル構成）、タスクトレイ常駐アプリプロセス設計書6章（自動起動）、エラーコード一覧・例外設計書E8001/E8002/E8003

## 1. 確認事項の反映結果

| 項目 | 決定内容 |
|---|---|
| 配布形式 | ポータブルZip配布。インストーラ（Inno Setup等）は作成しない。解凍後そのまま実行可能な構成とする |
| 管理者権限 | 常時管理者権限で起動。exeマニフェストに`requireAdministrator`を指定し、起動のたびにUACプロンプトが表示される |
| 配置場所 | ユーザーが任意の場所に配置（Program Filesのような固定領域を前提にしない。USB等へのポータブル配置も許容） |

## 2. 配布物構成

### 2.1 Zipパッケージ内容

```text
ClamAVFrontend_v1.0.0_win64.zip
└── ClamAVFrontend/
    ├── ClamAVFrontend.exe        # PyInstallerビルド成果物（--onedir、詳細は3章）
    ├── _internal/                # PyInstaller依存ライブラリ一式（--onedir方式の場合）
    ├── config.json               # 初回展開時は同梱しない（初回起動時に自動生成、4章参照）
    ├── logs/                     # 空ディレクトリ（初回起動時に自動作成でも可、同梱は任意）
    ├── quarantine/                # 空ディレクトリ（同上）
    ├── README.md                 # 日本語（リポジトリ直下のREADME.mdを同梱）
    └── README_en.md              # 英語（リポジトリ直下のREADME_en.mdを同梱）
```

Phase 11でREADMEをリポジトリ直下の `README.md`（日本語）/ `README_en.md`（英語）に一本化した（GitHubのリポジトリ説明と配布物の説明書を兼ねる）。`build_release.py` が両ファイルを配布物へコピーし、見つからない場合はビルドを中断する。

### 2.2 --onedir と --onefile の選定

- **--onedir方式を採用する**（sample/ClamQt6のREADME等から単一exe化の要望が過去にあった可能性はあるが、本アプリはリアルタイム監視・スケジューラ等の常駐サービスを含み起動速度が重要なため、展開処理が発生する--onefileより起動が高速な--onedirを優先する）
- Zip配布によって「1ファイルにまとまっていない使いにくさ」は解消されるため、--onefileのメリット（単一exe）は本配布形式では相対的に薄い

## 3. PyInstallerビルド設計

### 3.1 ビルドコマンド方針（spec化）

`ClamAVFrontend.spec`を用意し、以下の内容を管理する。

```python
# ClamAVFrontend.spec（要点のみ抜粋）
a = Analysis(
    ['app.py'],
    pathex=[],
    binaries=[],
    datas=[
        ('icons/*.png', 'icons'),
        ('manual/*', 'manual'),
    ],
    hiddenimports=['win32timezone'],  # APScheduler/pywin32系で必要になりやすいモジュールを明示
)

exe = EXE(
    ...,
    name='ClamAVFrontend',
    console=False,          # GUIアプリのためコンソール非表示
    icon='icons/clamQt.png',
    uac_admin=True,         # 4章: requireAdministrator相当のマニフェスト埋め込み
)
```

- `uac_admin=True`はPyInstallerが自動的にマニフェストへ`requestedExecutionLevel level="requireAdministrator"`を埋め込むオプションであり、これにより2.2節「常時管理者権限で起動」を実現する
- サイズ最適化（既存のpos_viewer.py開発時の知見と同様）として、不要な依存の`excludes`指定、UPX圧縮の要否は検証の上で判断する（過度なUPX圧縮はウイルス対策ソフト自体の誤検知を招くリスクがあるため、本アプリの性質上UPXは使用しない方針とする）

### 3.2 バージョン情報埋め込み

- Windows実行ファイルのバージョンリソース（`version_info`）にアプリバージョン、会社名、製品名を埋め込み、エクスプローラのプロパティから確認可能にする
- アプリ内バージョン表示は設定画面または「バージョン情報」ダイアログ（既存sample/ClamQt6のabout.htmlに相当する導線）に表示する

## 4. 管理者権限（UAC）の設計

### 4.1 常時管理者権限とする理由

- 隔離操作（読み取り専用・実行不可権限への変更、要件定義書3章）、リアルタイム監視の`ReadDirectoryChangesW`によるシステム全体監視、レジストリRunキーへの書き込み（自動起動設定）など、管理者権限を要する操作が多岐にわたるため、都度昇格ではなくアプリ全体を管理者権限で起動する方式を採用する

### 4.2 起動時の挙動

1. `ClamAVFrontend.exe`をユーザーが実行（ダブルクリック、または3-6節の自動起動経由）
2. Windowsが`requireAdministrator`マニフェストを検知しUACプロンプトを表示
3. ユーザーが「はい」を選択 → プロセスが管理者権限で起動
4. 「いいえ」を選択した場合 → プロセスは起動しない（何も表示されず終了。エクスプローラ実行時はWindows標準の挙動に従う）

### 4.3 自動起動（レジストリRunキー）との整合

- タスクトレイ常駐アプリプロセス設計書6.1節で定めたレジストリRunキー方式は、**Runキー経由の起動であっても`requireAdministrator`マニフェストがあればUACプロンプトが表示される**点に注意が必要
- これはOS起動時に毎回UACプロンプトが出ることを意味し、「タスクトレイ常駐アプリとして自動起動する」というユーザー体験を損なう可能性がある
- 対応方針：Windows OS標準の制約であるため、初版ではこの挙動を受け入れる。ユーザー向けドキュメント（README）に「自動起動時もUAC確認が表示されます。許可しない場合、保護機能は動作しません」と明記する
- 恒久対策（タスクスケジューラの「最上位の特権で実行」設定を利用したUACダイアログなしの管理者起動）は「未確定事項」（8章）に送る

### 4.4 権限不足エラーとの対応

- 常時管理者権限起動が前提のため、エラーコード一覧のE8001（管理者権限不足）は理論上「UACで拒否された場合」または「管理者権限を持たないユーザーアカウントでの実行」に限定される
- 後者の場合、アプリはそもそも起動できない（4.2節）ため、E8001は主にログ上の記録用として位置付ける

## 5. インストール先・初期化フロー

### 5.1 配置場所の扱い

- インストーラを介さないため「インストール先」という概念はなく、ユーザーがZipを展開した場所がそのまま実行場所になる
- 推奨配置例をREADMEに記載する（例: `C:\Tools\ClamAVFrontend\`、ユーザーのホーム配下等）。**システム保護領域（`C:\Windows`等）への配置は避けるよう注記**する（書き込み権限問題を避けるため。config.jsonスキーマ定義書2.2節の書き込み失敗リスクと連動）

### 5.2 初回起動時の初期化

1. `config.json`が存在しない → 既定値で新規作成（config.jsonスキーマ定義書2.3節）
2. `logs/`, `quarantine/`ディレクトリが存在しない → 自動作成
3. SQLite DBファイル（`app.db`等、ファイル名は詳細設計側で確定）が存在しない → `DatabaseService`が新規作成しテーブルを初期化（マイグレーション初期状態）
4. リアルタイム画面の監視対象パス未設定 → Windowsリアルタイム監視詳細設計書3.1節の初回案内ダイアログへ

### 5.3 前提ソフトウェアの確認

- 本アプリ自体はclamd/freshclamを同梱しない（ClamAV本体は別途インストールされている前提）
- 起動時、`ClamAVService.ping()`が失敗し続ける場合、エラーコードE1001のダイアログに加えて「ClamAVがインストールされていない可能性があります。公式サイトからインストールしてください」という追加の案内文を表示する（初回起動時のみ、通常のE1001ダイアログとは別に判定フラグを設ける）

## 6. アンインストール

- インストーラを使わないポータブル配布のため、アンインストールは以下をユーザー自身が行う想定とする（アンインストーラは提供しない）。
  1. トレイメニューからアプリを終了
  2. レジストリRunキー（自動起動設定）を設定画面からOFFにしてから削除、またはREADME記載のレジストリパスを手動削除
  3. Zipを展開したフォルダごと削除
- README（README.md / README_en.md）に上記手順を明記する

------------------------------------------------------------------------

## 7. バージョンアップ時の配布方針

- 「フロントエンド自己更新」は要件定義書8章の保留機能のため、初版では実装しない
- 新バージョンは新しいZipを別途ダウンロードし、旧フォルダを置き換える形を想定する。ただし`config.json`（ポータブル配置）は新フォルダへの手動コピーが必要になる点をREADMEに明記する（config.jsonスキーマ定義書1章のschema_versionは、将来この置き換え時の互換性チェックに利用される想定）

## 8. 未確定事項（次工程で決定が必要）

1. タスクスケジューラを用いた「UACダイアログなしでの管理者権限自動起動」の採用可否（4.3節の恒久対策候補。実現する場合はタスクトレイ常駐アプリプロセス設計書6.1節の自動起動方式自体を変更する必要がある）
2. SQLite DBファイル名・配置場所の正式決定（現状`db/database.py`モジュール名のみ既知、ファイル名は詳細設計側で確定が必要）
3. コード署名（Authenticode）の要否。署名なしの場合、SmartScreenの警告表示や、常時管理者権限起動と相まってユーザーの不信感を招く可能性があるため運用上の判断が必要
4. UPX非使用方針の最終確認（ビルドサイズとウイルス対策ソフト誤検知リスクのトレードオフ）

## 9. Phase 11 改訂（実装で確定した仕様）

### 9.1 配布物の軽量化（8章 未確定事項4の決定）
- 本アプリが使うQtモジュールはQtCore/QtGui/QtWidgetsのみのため、PySide6のフックが同梱する未使用の部品を`ClamAVFrontend.spec`で除外する
  - 除外: Qt6Network/OpenGL/Pdf/Qml/Quick/Svg/VirtualKeyboard、`opengl32sw.dll`（ソフトウェアOpenGL）、Qtの翻訳ファイル、QtのTLSプラグイン用OpenSSL（`libcrypto-3-x64`/`libssl-3-x64`）
  - 残すプラグイン: `platforms/qwindows`（ウィンドウ表示）、`styles/qmodernwindowsstyle`（Windows 11スタイル）、`imageformats/qico`（.ico読込）。Linuxビルド用に`libqxcb`/`libqwayland`/`libqico`も残す
  - Python側のSSL（SMTP送信）が使う`libssl-3.dll`/`libcrypto-3.dll`は残す
- 結果（Windows）: Zip 60.8MB → 37.1MB、展開後 134.6MB → 75.3MB。起動・アイコン表示・トレイからの終了を実機で確認した
- exe本体（約11MB）にはPythonモジュール一式が含まれる。onedir方式のため、exeを複数に分割しても合計サイズは減らない

### 9.1.1 通知クリック用の補助プログラム（Windows）
- `ClamAVFrontendActivate.exe`（約2MB）を本体と同じフォルダに同梱する。`notify_activate.py`を標準ライブラリのみでexe化したもので、console=False（ウィンドウなし）・uac_admin=False（asInvoker、UAC不要）。`_internal/`のPython DLLを本体と共有する
- 通知（Toast）のクリックで起動され、依頼ファイルを書いて終了する（通知機能詳細仕様書9章）
- 同梱後の配布物: Zip 39.0MB、展開後 77.3MB

### 9.2 アイコン
- `icons/clamQt.ico`（exeのアイコン、16〜256px）と`icons/tray_*.png`（トレイ）は`scripts/generate_icons.py`で生成する。ClamAV公式ロゴは商標のため使わない
- 同梱リソース（`icons/`等）はフリーズ時`_internal/`（`sys._MEIPASS`）に展開されるため、app.pyは読み取り専用リソースを`_RESOURCE_DIR`から参照する（書き込み先の`_APP_DIR`とは別）

### 9.3 README・ライセンス
- READMEはリポジトリ直下の`README.md`（日本語）/`README_en.md`（英語）に一本化し、`LICENSE`（MIT）とあわせて`build_release.py`が配布物へ同梱する（2.1節）
