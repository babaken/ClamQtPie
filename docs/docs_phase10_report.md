## 4. Phase10で新たに発見・修正した不具合

### 4.1 `_run_scheduled_scan()`（app.py）のScanWorker引数名誤り

**事象**: `app.py`のスケジュールスキャン実行用クロージャが`ScanWorker(..., recursive=True, ...)`という存在しない引数名で`ScanWorker`を呼び出しており、実際にスケジュールされたスキャンジョブが実行されると`TypeError`で失敗する状態だった（正しい引数名は`include_subfolders`）。

**発覚経緯**: Phase10のフルスキャン性能検証スクリプト作成中、検証用コードで同じ誤った引数名を使ってしまい`TypeError`が発生。これをきっかけに`app.py`本体の同一箇所も確認したところ、Phase6でこのクロージャを実装して以来、一度も実際に呼び出されるテストが存在しなかった（`SchedulerService`の単体テストは`run_scan`コールバックをモック化していたため、クロージャの中身自体は検証対象外だった）ため見過ごされていたことが判明した。

**教訓**: コールバックとして注入する関数・クロージャは、注入先のテストではモック化されるため、クロージャ自身の実装は別途直接検証しないと見逃される。結合検証（Phase10）で初めて発覚した典型例であり、「各フェーズの単体テストが緑でも、フェーズをまたぐ結線部分は別途確認が要る」という設計書がPhase10を独立フェーズとして設けている理由を体現する事例だった。

**対応**: `app.py`の該当箇所を修正し、再発防止のため`tests/unit/test_scheduled_scan_regression.py`を新規追加した（実際のクロージャと同一の引数の組み合わせでScanWorkerを構築・実行し、TypeErrorが発生しないことを確認する）。

## 5. 未実施・Windows実機が必要な項目

以下はLinux開発コンテナでは検証不可能なため、Windows実機での実施が必須となる（テスト仕様書7章 未確定事項1と同一の制約）。

1. UACプロンプトの実表示・「常時管理者権限起動」の実地確認
2. レジストリRunキーによる自動起動時、OS起動のたびにUACが表示される制約の実地確認（インストーラ/パッケージング設計書4.3節）
3. PowerShell ToastNotificationManagerによる通知の実表示・内容確認
4. `watchdog`のWindows実装（`ReadDirectoryChangesW`経由）での動作確認（Linuxでは`inotify`経由のため、Windows固有の挙動差異がないか要確認）
5. 実際のPyInstaller `.exe`ビルド（本レポートの検証はLinuxバイナリでの代替検証）
6. 実clamd環境でのフルスキャン所要時間（本レポート2.3節はモックサーバでのアプリ側オーバーヘッドのみの計測）

## 6. 総合判定

自動テスト・性能検証・自動化可能な範囲の手動確認チェックリストはすべて基準を満たした。Windows固有の項目（UAC・レジストリ自動起動・Toast通知）およびLinuxでの`notify-send`実表示は、実機・実環境がない本開発コンテナでは検証できないため、リリース前に別途実施が必要な残課題として明記する。

実装ステップ計画書のマイルストーンM6（リリース版: 全テスト・非機能要件クリア）は、上記Windows実機確認を除き、本コンテナで実施可能な範囲において達成した。
